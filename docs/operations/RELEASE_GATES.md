# Release gates
Policies are immutable project records with a monotonically increasing version per name. Admins create them; developers evaluate them; viewers inspect evidence. The default is a native smoke policy, not a production certification: 80% task success, zero confirmed critical findings, P95 <=1000ms, eight distinct scenario samples and native suite coverage.

Configure min_success, max_critical, max_latency_ms, min_samples, required_scenarios, required_benchmarks, required_reviews, required_review_approvals, required_security_checks, max_high, max_cost and regression_tolerance through POST /projects/{id}/policies. Missing required coverage, cost, reviews, compatible baseline or samples yields INCONCLUSIVE. Confirmed policy violations yield FAIL even if other evidence is missing. Automatic findings are preserved. honor_human_overrides is false by default; when explicitly enabled, the latest audited reviewer outcome overrides task scoring for release only. INCONCLUSIVE reviewer outcomes leave release scoring inconclusive. Overrides never erase automatic summary or critical security findings.

A policy requiring a baseline uses baseline_id on POST /runs/{id}/release. Scenario sets, suite version, trials, seed, execution backend and dataset fingerprint must match. Paired statistics cluster repeated deterministic trials by scenario; small differences are not automatically significant.

`scripts/demo.py` exits 0 for PASS, 1 for FAIL and 2 for INCONCLUSIVE. `.github/workflows/release-example.yml` runs the candidate configuration on PRs.
